# 학교시설업무 BIBLE 요약문서 생성

법령·고시·매뉴얼 원문을 A4 HTML 요약문서로 변환한다. 디자인 규격이 고정되어 있고, **분량이 규격을 넘으면 내용이 잘려 나가므로 반드시 실측 검증을 거친다.**

## 절대 원칙

1. **`overflow:hidden`으로 분량을 제한하지 않는다.** 내용이 조용히 잘린다. 넘치면 내용을 줄인다.
2. **눈대중으로 분량을 판단하지 않는다.** 반드시 `scripts/verify.py`로 실측한다.
3. **원문에 없는 수치를 쓰지 않는다.** 확인되지 않으면 해당 항목을 뺀다.
4. **원문이 오래된 경우 개정 여부를 확인하고 사용자에게 알린다.** (예: 산업안전보건법은 2019년 전부개정으로 조문 번호가 전부 바뀜)

## 작업 순서

### 1단계 — 원문 판독

```bash
pdfinfo "원문.pdf" | grep -i pages
pdftotext -layout "원문.pdf" /tmp/src.txt
wc -c /tmp/src.txt
```

추출 문자 수가 페이지당 200자 미만이면 **스캔본**이다. OCR로 전환한다.

```bash
# 한국어 OCR 언어팩 확보 (컨테이너에 kor이 없는 경우)
curl -sL -o /tmp/tessdata/kor.traineddata \
  https://raw.githubusercontent.com/tesseract-ocr/tessdata_fast/main/kor.traineddata
export TESSDATA_PREFIX=/tmp/tessdata
pdftoppm -jpeg -r 150 -f 4 -l 9 "원문.pdf" /tmp/p
for f in /tmp/p-*.jpg; do tesseract $f - -l kor --psm 6; done
```

목차를 먼저 읽어 장 구조를 파악한 뒤, **수치·기한·요율·기준금액이 있는 절만 골라** 발췌한다. 전문을 읽지 않는다.

```bash
grep -nE "이상|이하|이내|일 전|개월|퍼센트|%|억원|만원" /tmp/src.txt | head -40
```

### 2단계 — 분량 결정

**원칙: 가급적 A4 1장을 목표로 한다.** 특히 '핵심 요약', '한 장 요약', '원페이퍼' 요청은 **1장 우선**으로, 가장 실무적으로 필요한 항목만 추려 한 장에 담는다. 다만 **문서(원문)의 분량·범위에 따라 여러 장도 가능**하다 — 절차가 여러 단계이거나 수치·기준이 많아 한 장에 담으면 실무 데이터가 잘리는 경우에는 억지로 1장에 압축하지 말고 페이지를 나눈다. 즉 **기본은 1장, 필요하면 다장.**

| 원문 성격 | 쪽수 |
|---|---|
| 단일 고시·지침, 절차가 하나 / 핵심 요약 요청 | **1쪽** |
| 해설집·질의회시집 | 1쪽 (질의응답은 별도 문서로 분리 제안) |
| 생애주기형 매뉴얼(기획→설계→시공→준공→유지관리) | **단계당 1쪽 + 총론 1쪽** |
| 200쪽 이상 종합 매뉴얼 | 4~6쪽 |

쪽수를 사용자가 지정하지 않았고 원문이 100쪽을 넘으면, 결정한 쪽수와 그 근거를 답변에 밝힌다.

### 3단계 — 내용 설계

각 쪽은 고정 구조를 따른다. 자세한 규격은 `references/design-spec.md` 참조.

```
제목 → 메타 1줄 → 네이비 룰
[1 | 2]  2단 카드
[3]      전폭 · 러스트 배지 · 수식 밴드 · ①~④ 번호항목
[4 | 5]  2단 카드
[6]      전폭 · 칩
회색 룰 → 중앙 각주
```

- 3번 섹션은 **그 문서의 핵심 계산식 또는 절차 타임라인**을 배치한다. 산정식이 없는 절차형 주제는 밴드에 시간 흐름을 넣는다.
- 6번 칩은 본문에 나온 수치를 재확인용으로 나열한다.
- 다쪽 문서는 7번 카드(전폭)를 추가해도 된다.

**분량 상한(실측값)**

| 항목 | 실측 |
|---|---|
| 본문 1행 | 4.28mm (6.7pt = 9px, 행간 1.42 + 항목여백 0.9mm) |
| 빈 카드(배지+패딩+테두리) | 8.5mm |
| 2단 카드 1행 수용 글자 수 | 약 35자 |
| 전폭 카드 1행 수용 글자 수 | 약 75자 |
| 칩 1줄 | 5.9mm |

| 형식 | 콘텐츠 하단 한계 | 권장 |
|---|---|---|
| 1쪽 문서 | **163mm**(상단 55%) | 155mm 이하 |
| 다쪽 문서 | 283mm | 210~225mm(70~75%) |

1쪽 문서의 실질 수용량은 **카드당 항목 4개·각 1행, 3번 섹션은 밴드 1행 + ①~④ 각 1~2행, 칩 10개**다. 이보다 늘리면 반드시 초과한다.

### 4단계 — 빌드

`assets/base.css`를 그대로 사용한다. 색상·서체·크기를 임의로 바꾸지 않는다.

```bash
cp -r <스킬경로>/assets /tmp/build/
cp <스킬경로>/scripts/* /tmp/build/
cd /tmp/build
# body.html에 본문만 작성한 뒤
./mk.sh "제목" body.html out.html
```

### 5단계 — 검증 (생략 금지)

```bash
python3 verify.py out.html                # 1쪽 문서
python3 verify_fixed.py out.html --multi   # 다쪽 문서 (반드시 이것)
```

**다쪽 문서는 `verify_fixed.py`를 쓴다.** `verify.py`는 페이지를 정규식으로 잘라 카드·밴드 내부의 중첩 `</div>`에서 조용히 잘리고 높이를 잘못 읽는다. `verify_fixed.py`는 div 깊이를 세어 `.page` 블록을 정확히 분리한다.

**wkhtmltoimage는 CSS Grid를 지원하지 않는다.** 2단 카드가 세로로 쌓여 높이가 약 2배로 나온다. 두 스크립트 모두 측정 시에만 Grid를 table 레이아웃으로 치환하므로 배포 파일은 Grid 그대로 두면 된다.

초과가 나오면 이 순서로 줄인다.
1. 메타를 1줄로 축약
2. 칩 개수 축소
3. 카드 항목을 4개로, 각 항목을 1행 분량으로 축약
4. 3번 섹션 밴드의 부제(`.sub`) 삭제

적합 판정이 날 때까지 반복한다.

### 6단계 — 배포

`/mnt/user-data/outputs/`에 `번호_주제_요약.html` 형식으로 저장하고 `present_files`로 제시한다.

- 번호는 두 자리(`01`, `02`…). 사용자가 체계를 지정하지 않았으면 임의 부여 후 "조정 가능"임을 밝힌다.
- 주제는 공백 없이 붙여 쓴다. 예: `02_학교시설석면해체제거_요약.html`

## 답변에 포함할 내용

- 원문 서지사항(발간기관·발간일·쪽수)과 판독 방식(스캔본이면 OCR 사용 사실)
- 섹션별 수록 내용
- 검증 결과(콘텐츠 하단 mm, 사용률)
- 의도적으로 제외한 내용과 그 이유
- 원문의 개정·폐지 의심 사항

## 가독성 변형 (readable)

사용자가 **'가독성', 'readable', '글씨 키워', '레이아웃 읽기 쉽게'** 등을 요청하면 `assets/base.css` 대신 `assets/base_readable.css`를 쓴다. 색상·구조·클래스는 동일하고 타이포·행간·여백만 확대한다.

| 요소 | 기본 → readable |
|---|---|
| 본문·항목 | 6.7pt/1.42 → **7.5pt/1.52** |
| 제목 | 13.1pt → 14pt |
| 배지 | 7.9pt → 8.4pt |
| 칩 | 6pt → 6.6pt |
| 좌우 여백 | 12mm → **10mm**(줄바꿈 감소) |

**주의: 큰 타이포에서는 한 쪽 수용량이 준다.** 카드 6~7개가 한 페이지에 몰리면 A4 한계(283mm)를 초과한다. 초과하면 아래 '다쪽 문서 편집'의 분할을 적용한다. 원본을 덮어쓰지 않고 별도 파일로 만든다.

## 다쪽 문서 편집 (페이지 추가·분할)

기존 다쪽 BIBLE 문서에 페이지를 붙이거나 나눌 때:

1. 업로드본을 작업 폴더로 복사(업로드 폴더는 읽기 전용).
2. **`.page` 블록은 div 깊이로 분리한다**(정규식 금지 — 중첩 `</div>`에서 잘림). `verify_fixed.py`의 `split_pages()` 로직을 그대로 쓴다.
3. 새 쪽 본문을 작성하고 `</body>` 앞에 삽입한다. 카드 배지는 각 쪽 1..N으로 다시 매긴다.
4. **쪽번호를 일괄 갱신**한다(`>n / 4<` → `>n / 5<` 전부, 새 쪽에 `n / N` 추가).
5. `verify_fixed.py --multi`로 **모든 쪽**을 실측한다. 새 쪽뿐 아니라 기존 쪽 리듬(사용률)도 확인해 톤을 맞춘다.
6. 한 쪽이 283mm를 초과하면 카드를 두 쪽으로 나눈다. 분할 시 각 쪽 배지를 1..N으로 재부여하고 쪽번호·원문자(⑤⑥)를 갱신한다. readable 크기에서는 카드 4개 안팎이 한 쪽의 적정 분량이다.

원문에 없는 내용(예: 감리대상)을 추가할 때는 **법령 MCP로 근거 조문을 확인**하고, 각주에 근거를 명시한다.

## 인포그래픽 스타일 변형 (infographic)

사용자가 참고 인포그래픽을 첨부하며 **'이 스타일로', '그림처럼'** 요청하거나 시각적 임팩트를 원하면 `assets/base_infographic.css`를 쓴다. 네이비(#1B3A5B)→틸(#227C8E) 그라데이션 언어다.

- **팔레트** — 네이비+틸 그라데이션, 열린 카드(좌우 세로 테두리 없이 **상하 가로 라인만**, 그림자·라운드 없음), 라이트 블루그레이 패널, 틸 강조.
- **SVG 아이콘 필수, 이모지 금지** — 사용자 피드백: **"이모지는 촌스럽다."** 섹션 배지·제목에는 그라데이션 타일 안의 흰색 SVG 라인 아이콘을 넣는다. 아이콘 라이브러리와 배지 매핑은 `scripts/infographic_icons.py`에 있다(문서·검토·크레인·방패·안전모·잎·폭발·학교·클립보드 등 22종).
- **틸 넘버서클** — `.nlist .no`가 원 안 흰 숫자.
- **제목** — 18pt + 틸 그라데이션 언더바, `white-space:nowrap`로 **한 줄 유지**. 넘치면 접두어를 줄인다(폭은 `verify` 방식으로 실측; 190mm 이내).
- **한줄 결론 밴드** — 마지막 페이지에 `.conclude`(네이비→틸 그라데이션) 삽입. 재분할 시 밴드 높이(약 22mm)를 마지막 챕터 예산에서 빼 초과를 막는다.
- **완성 예시** — `references/infographic_exemplar.html`(11쪽 완본: SVG 아이콘·틸 넘버서클·역할 강조 콜아웃·결론 밴드·출처 각주 포함). 구조와 마크업을 그대로 참고한다.

### 「핵심 수치 재확인」은 페이지 하단 고정 — 필수

각 페이지의 **'핵심 수치 재확인' 카드(칩 모음)는 반드시 페이지 하단에 오게 한다**(사용자 요구). 방법:
- 그 카드의 `.row1`에 **`recap` 클래스**를 준다 → `.row1.recap{ margin-top:auto }`로 아래로 밀린다.
- 그 카드가 있는 `.page`에 **`haspin` 클래스**를 준다 → `.page.haspin`가 A4 전체높이(297mm) 세로 플렉스가 되어 하단 정렬이 가능해진다. recap 카드가 없는 페이지는 `haspin`을 주지 않아 컴팩트(여백 최소)로 둔다.
- 결과 순서: 상단(제목·상단 카드) → **여백** → 하단(핵심 수치 카드 → 결론 밴드 → 출처·쪽번호).
- **검증** — `haspin` 페이지는 footer가 시트 하단(~289mm)에 오는 것이 정상이다. `verify_fixed.py`가 측정 시 `haspin`/`recap`을 무력화해 **실제 콘텐츠 높이(283mm 기준)로 판정**하므로 오탐하지 않는다.

### 역할(책임 주체) 강조 — 필수

**발주청·감독자·감리자·허가권자·관리주체 등 '누가 책임지는가'가 나오는 카드에는 강조를 반드시 넣는다**(사용자 요구: "발주청·감독자 이런 내용엔 강조 문구가 꼭 들어가야 해").

- `.rolebar` — 앰버(#FDF0E1) 바 + 오렌지(#D9730D) **인물 아이콘 타일** + 굵은 강조 문구. 역할 정의를 한 줄로 명시(예: "**발주청 = 학교·교육청** — 해체 발주·감독의 책임 주체"). 헬퍼: `infographic_icons.rolebar()`.
- `.rolet` — 본문 역할어를 앰버 볼드 텍스트로 색상 강조.
- 워밍 앰버는 네이비·틸과 대비되어 책임 주체가 즉시 눈에 띈다. 오렌지는 이 역할 강조와 핵심 수치에만 쓴다(남용 금지).

## 노션 스타일 변형 (notion)

사용자가 **'노션스타일로', '노션 스킬 적용'** 등을 요청하면 `assets/base_notion.css`를 쓴다. 엑셀 `excel-notion-style` 스킬의 팔레트를 이식한 것으로, 색상 일관성을 위해 그 스킬을 먼저 참고한다.

- **핵심 원칙** — 노션은 파랑이 아니라 **웜그레이 + 저채도 오렌지 액센트**다. 네이비·로열블루를 남발하면 노션처럼 안 보인다. 네이비는 헤더·구조선에만, 파랑 계열 강조는 쓰지 않는다.
- **팔레트** — 본문 #37352F / 보조 #787774 / 각주 #9B9A97, 액센트 #D9730D·#B45309, 웜그레이 카드 #F7F6F3·#F1F0ED, 테두리 #E3E2DE·#C7C5C0, 헤더 네이비 #1E3A5F.
- **오렌지는 절제** — 핵심 수치(`.num`)와 중요 강조(`.hl`, `.badge.emph`)에만. 장식용 오렌지 배지를 늘리지 않는다.
- **이모지 섹션 아이콘** — 노션 콜아웃처럼 각 배지 앞에 주제 이모지를 넣는다(📋 허가, 🔍 검토, 🏗️ 장비, 🛡️ 구조안전, 👷 안전/감리, ♻️ 환경, 💥 폭파, 🏫 학교, 📌 핵심수치 등). 미리보기(wkhtmltoimage)에서는 흑백으로 보여도 브라우저에서는 컬러로 렌더된다.
- **중요부 강조 클래스** — `.badge.emph`(오렌지 배지)와 `.hl`(오렌지 강조 글씨)로 특정 주체·항목을 부각한다. 예: 발주청은 배지를 `emph`로, "학교·교육청 = 발주청"을 `.hl`로 표시.

### 인쇄용 무채움

인쇄가 목적이면(**'인쇄해야 하니 배경 색채우기 하지 마'**) 배경 채움을 전부 없애고 **테두리·좌측 바·글자색·굵기**로만 구조를 표현한다. `base_notion.css` 기본값이 이미 무채움이며, 화면용 채움으로 되돌리는 값은 파일 상단 주석에 있다. `print-color-adjust:exact`는 무채움에서 제거한다. 화면 구분용 회색 배경은 `@media screen`에만 두어 인쇄물에 나오지 않게 한다.

### 1단 순차 배열 + 균등 분할

**'2단 지양·1단 순차 나열'** 요청 시 모든 카드를 전폭 단일 열(`.row1`)로 세로 나열한다. 1단은 페이지가 길어지므로 **챕터별로 카드를 균등 분할**한다 — 그리디로 채우면 마지막 페이지가 5+1처럼 반쯤 비므로, 카드 높이를 실측해 **연속 분할 중 max 페이지 높이를 최소화**하는 지점으로 3+3처럼 나눈다(`itertools.combinations`로 분할점 탐색, 각 후보를 실측). 분할된 후속 페이지 제목에는 "(계속)"을 붙이고 쪽번호·배지 번호는 순차 유지한다.

### 자료 출처 사이트

원문 매뉴얼·사례집을 요약할 때 **출처 사이트를 각주에 명시**한다. 웹 검색으로 실제 게시 경로를 확인하고 임의 URL을 만들지 않는다(예: 해체 사례집 → 국토안전관리원 www.kalis.or.kr · 건축물관리지원센터 www.kbmsc.or.kr).

## 하단 여백 최소 옵션

사용자가 **'하단 여백 최소', '빈 공간 줄여'** 등을 요청하면, `.page`의 `min-height:297mm`를 제거(또는 주석 처리)하여 페이지가 내용 높이에 맞게 줄도록 한다. 하단 패딩도 14mm→6~7mm로 줄인다. `page-break-after:always`와 `@page A4`는 유지하므로 **인쇄는 그대로 한 쪽씩 A4 한 장**에 나온다(화면·PDF의 하단 빈 공간만 사라진다).

## 흔한 실패

| 증상 | 원인 | 조치 |
|---|---|---|
| 4번 이하 카드가 안 보임 | `overflow:hidden` + 분량 초과 | hidden 제거 후 내용 축약 |
| 배지 글자가 잘림 | 배지 줄바꿈 | `white-space:nowrap` 확인 |
| 측정값이 실제보다 2배 | Grid 미지원 렌더러 | Grid→table 치환(스크립트가 자동 수행) |
| 다쪽 높이가 실제보다 작게 나옴 | `verify.py` 정규식이 중첩 `</div>`에서 잘림 | 다쪽은 `verify_fixed.py --multi` 사용 |
| readable에서 페이지 초과 | 큰 타이포에 카드 과다 | 페이지 분할(다쪽 문서 편집 참조) |
| 숫자가 원문과 다름 | 요율표 개정 미반영 | 시행일 기준 최신 별표 확인 |
